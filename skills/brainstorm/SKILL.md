# Brainstorm

Expand the option space before converging.

First establish the real problem, affected users or callers, constraints, and what success changes. Inspect repository facts (via the `Explore` agent) when they would eliminate invented ideas. Ask one focused question when the problem itself is unclear.

Generate at least three materially different approaches, not cosmetic variations. Include one conservative extension of the current design, one structurally different approach, and one cheap experiment or prototype when useful. For each, identify the core idea, upside, cost, failure mode, reversibility, and the evidence that would favor it.

Challenge the framing and surface assumptions, but do not turn the session into an exhaustive requirements interview. Do not implement, write a work plan, or force a recommendation prematurely. End with the most useful next decision or experiment. Recommend an option only when the user asks or the evidence clearly dominates.
